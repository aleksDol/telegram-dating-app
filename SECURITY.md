# Отчёт по безопасности проекта

## Что уже сделано хорошо

- **SQL-инъекции**: Все запросы к БД используют параметризованные плейсхолдеры (`?` / `%s`). Пользовательский ввод не подставляется в SQL строкой.
- **Аутентификация Mini App**: Проверка `initData` от Telegram через HMAC (ключ из BOT_TOKEN). Подделать пользователя без знания токена бота нельзя.
- **Админка**: JWT с секретом `TOKEN_ADMIN`, логин/пароль и токен в `.env`. Эндпоинты `/admin/api/*` защищены.
- **XSS**: В веб-админке используется `escapeHtml` при выводе данных; в боте — `escape_markdown` для Telegram.
- **HTTPS**: В nginx настроен редирект HTTP → HTTPS и SSL для домена.
- **Размер загрузки**: Лимит 10 МБ на API и `client_max_body_size 10m` в nginx.

---

## Внесённые исправления

1. **Загрузка фото**  
   Добавлена проверка magic bytes (JPEG, PNG, WebP). Принимаются только реальные изображения, а не файлы с подменённым MIME.

2. **Рассылка типа «Ссылка»**  
   Разрешены только URL с `http://` или `https://`. Запрещены `javascript:`, `data:` и т.п. В href экранируются кавычки.

3. **Длина полей и возраст**  
   В Pydantic-моделях API добавлены ограничения:
   - имя, город, цель, заголовок, описание — ограничение длины;
   - возраст — от 18 до 120.

4. **Фото в рассылке (base64)**  
   При декодировании base64 для рассылки проверяются magic bytes изображения.

## Рекомендации (без изменений кода)

1. **X-Dev-User-Id**  
   Заголовок `X-Dev-User-Id` позволяет на localhost войти без Telegram. В **production** обязательно отключить: `ALLOW_DEV_USER_ID=0` или не задавать. Иначе любой может подставить чужой `user_id`.

2. **TOKEN_ADMIN**  
   В коде используется `config.TOKEN_ADMIN or "secret"`. В production **обязательно** задать сильный `TOKEN_ADMIN` в `.env`. Не оставлять значение по умолчанию.

3. **initData в URL**  
   Если Mini App открывается с `tgWebAppData` в URL, не логировать полный URL (в access.log и т.д.), чтобы не сохранять токен.

4. **CORS**  
   `ADDITIONAL_CORS_ORIGINS` добавляет доверенные origin. В production указывать только нужные домены.

5. **Пароли и секреты**  
   Хранить в переменных окружения (`.env`), не коммитить в репозиторий. В `.env.example` оставить только имена переменных без реальных значений.
